# AgentScope 设计文档

> 本文档从架构设计角度分析 AgentScope 框架的核心设计理念、模块间关系、关键设计模式和扩展机制。

---

## 1. 架构总览

AgentScope 采用**分层模块化架构**，以智能体（Agent）为中心，围绕其构建了模型、记忆、工具、消息、格式化器、流水线等配套模块。

```
┌─────────────────────────────────────────────────────────────┐
│                     Application Layer                        │
│         (examples / 用户自定义智能体应用)                      │
├─────────────────────────────────────────────────────────────┤
│                     Pipeline Layer                           │
│    SequentialPipeline / FanoutPipeline / MsgHub / ChatRoom   │
├─────────────────────────────────────────────────────────────┤
│                      Agent Layer                             │
│  AgentBase → ReActAgentBase → ReActAgent                     │
│  UserAgent / A2AAgent / RealtimeAgent                        │
├──────┬──────┬──────┬──────┬──────┬──────┬──────┬────────────┤
│Model │Memory│Tool  │Formt │ RAG  │ Plan │  TTS │ ...        │
│Layer │Layer │Layer │Layer │Layer │Layer │Layer │            │
├──────┴──────┴──────┴──────┴──────┴──────┴──────┴────────────┤
│                   Infrastructure Layer                       │
│  Message / Session / Tracing / Embedding / Token / Hooks     │
├─────────────────────────────────────────────────────────────┤
│                    Foundation Layer                           │
│  StateModule / _run_config(ContextVar) / _utils / Exception  │
└─────────────────────────────────────────────────────────────┘
```

## 2. 核心设计理念

### 2.1 异步优先（Async-First）

整个框架采用**异步优先**设计：

- 所有 Agent 的 `reply()` 和 `observe()` 方法均为 `async`
- 所有 Model 的 `__call__` 为 `async`，返回 `ChatResponse | AsyncGenerator[ChatResponse, None]`
- Pipeline 支持异步并发（`FanoutPipeline` 使用 `asyncio.gather()`）
- 工具函数通过 `_async_wrapper` 自动包装为异步生成器
- MCP 客户端全部基于异步 IO

**设计意图**: 多智能体系统天然适合异步并发，异步优先能充分利用 IO 等待时间，提升多 Agent 并行效率。

### 2.2 策略模式与可插拔架构

框架大量采用**策略模式**，每个核心能力通过抽象基类定义接口，具体实现可插拔替换：

```
ChatModelBase ← OpenAIChatModel / DashScopeChatModel / AnthropicChatModel / ...
FormatterBase ← OpenAIChatFormatter / DashScopeChatFormatter / ...
MemoryBase   ← InMemoryMemory / RedisMemory / AsyncSQLAlchemyMemory / ...
VDBStoreBase ← QdrantStore / MilvusStore / MongoDBStore / ...
```

**设计意图**: 模型提供商不断变化，通过策略模式用户可以轻松切换模型、存储后端等，无需修改业务逻辑。

### 2.3 组合优于继承

`ReActAgent` 通过**组合**而非继承来获得各种能力：

```python
class ReActAgent(ReActAgentBase):
    def __init__(
        self,
        model: ChatModelBase,           # 注入模型
        formatter: FormatterBase,        # 注入格式化器
        toolkit: Toolkit | None,         # 注入工具集
        memory: MemoryBase | None,       # 注入工作记忆
        long_term_memory: LongTermMemoryBase | None,  # 注入长期记忆
        knowledge: KnowledgeBase | None, # 注入知识库
        plan_notebook: PlanNotebook | None,  # 注入计划
        tts_model: TTSModelBase | None,  # 注入 TTS
        compression_config: CompressionConfig | None,  # 注入压缩配置
    ):
        ...
```

**设计意图**: 每个能力维度独立可选，用户按需组合，避免深层继承树带来的复杂性和耦合。

### 2.4 消息中心化（Message-Centric）

消息（`Msg`）是框架的**核心数据单元**，所有模块间的交互都通过消息传递：

- Agent 之间通过 `Msg` 通信
- 工具调用通过 `ToolUseBlock` / `ToolResultBlock` 承载
- 多模态内容通过各类 `ContentBlock` 承载
- Formatter 将 `Msg` 转换为模型 API 格式

**设计意图**: 统一的消息模型使得各模块解耦，任何模块只需理解消息格式即可参与协作。

## 3. 关键模块设计

### 3.1 Agent 层设计

#### 继承体系

```
StateModule (基础状态模块)
  └── AgentBase (智能体基类, metaclass=_AgentMeta)
        ├── ReActAgentBase (ReAct 基类)
        │     └── ReActAgent (核心智能体实现)
        ├── UserAgent (用户交互智能体)
        ├── A2AAgent (A2A 协议智能体)
        └── RealtimeAgent (实时语音智能体)
```

#### AgentBase 核心设计

1. **元类 `_AgentMeta`**: 用于自动收集和注册智能体类信息
2. **Hook 机制**: 六类钩子（`pre_reply`/`post_reply`/`pre_print`/`post_print`/`pre_observe`/`post_observe`），分**类级别**和**实例级别**
   - 类级别 Hook: 对所有实例生效，如 Studio 集成
   - 实例级别 Hook: 仅对特定实例生效
3. **订阅机制**: `_subscribers` 字典管理消息订阅者，MsgHub 通过此机制实现广播
4. **流式输出**: `_stream_prefix` 缓存流式输出中间状态，`msg_queue` 支持消息导出为生成器

#### ReActAgent 核心设计

ReActAgent 是框架的核心智能体，实现了完整的 **Reasoning-Action 循环**：

```
                    ┌──────────────────┐
                    │   用户消息输入     │
                    └───────┬──────────┘
                            ▼
                    ┌──────────────────┐
               ┌──▶│   记忆观察        │  ← 长期记忆检索（static_control 模式）
               │   └───────┬──────────┘
               │           ▼
               │   ┌──────────────────┐
               │   │   RAG 知识检索    │  ← 可选的查询重写
               │   └───────┬──────────┘
               │           ▼
               │   ┌──────────────────┐
               │   │   格式化消息      │  ← Formatter 转换
               │   └───────┬──────────┘
               │           ▼
               │   ┌──────────────────┐
               │   │   模型推理        │  ← ChatModel 调用
               │   └───────┬──────────┘
               │           ▼
               │   ┌──────────────────┐
               │   │  解析响应         │
               │   │  ├─ 文本 → 返回   │
    否         │   │  ├─ 工具调用 → 执行│──────────┐
───────────────│   │  └─ 结构化输出    │          │
               │   └───────┬──────────┘          │
               │           ▼                     ▼
               │   ┌──────────────────┐  ┌──────────────┐
               │   │   记忆压缩检查    │  │  执行工具调用  │
               │   └───────┬──────────┘  │  (可并行)     │
               │           │             └──────┬───────┘
               │           ▼                    │
               │   ┌──────────────────┐         │
               │   │  长期记忆记录     │◀────────┘
               │   │  (static_control) │
               │   └───────┬──────────┘
               │           │
               └───────────┘  (继续循环，最多 max_iters 次)
```

**关键能力**:

| 能力 | 设计 |
|---|---|
| 工具调用 | 通过 `Toolkit` 管理工具，支持并行调用 (`parallel_tool_calls`) |
| 记忆压缩 | `CompressionConfig` — 当 Token 超过阈值时，用结构化 SummarySchema 压缩历史记忆 |
| RAG | 支持多个 `KnowledgeBase`，可选 `enable_rewrite_query` 重写查询 |
| 长期记忆 | `LongTermMemoryBase` 支持 `agent_control`（工具函数）和 `static_control`（自动存取）两种模式 |
| 计划管理 | `PlanNotebook` 集成，支持子任务拆分和状态跟踪 |
| 元工具 | `enable_meta_tool` 开启后，Agent 可动态管理自身工具集 |
| 结构化输出 | `structured_model` 参数，通过 Pydantic BaseModel 约束输出格式 |
| TTS | `tts_model` 参数，Agent 回复可同时生成语音 |

### 3.2 Model 层设计

```
ChatModelBase (抽象基类)
  ├── model_name: str    # 模型名称
  ├── stream: bool       # 是否流式
  └── __call__() → ChatResponse | AsyncGenerator[ChatResponse]
       ├── OpenAIChatModel
       ├── DashScopeChatModel
       ├── AnthropicChatModel
       ├── GeminiChatModel
       ├── OllamaChatModel
       └── TrinityChatModel
```

**设计要点**:
- 模型与格式化器**分离** — `ChatModelBase` 只负责 API 调用，消息格式转换由 `FormatterBase` 负责
- 统一的 `ChatResponse` 返回类型
- 内置 `tool_choice` 验证（auto/none/required/指定函数名）
- 所有模型调用被 `trace_llm` 追踪

### 3.3 Formatter 层设计

格式化器负责**将内部 Msg 格式转换为目标模型 API 格式**，是 Model 与 Message 之间的桥梁：

```
FormatterBase (抽象基类)
  ├── ChatFormatter     — 单轮对话格式
  └── MultiAgentFormatter — 多智能体对话格式

每个模型提供商有两种格式化器:
  OpenAI:   OpenAIChatFormatter / OpenAIMultiAgentFormatter
  DashScope: DashScopeChatFormatter / DashScopeMultiAgentFormatter
  Anthropic: AnthropicChatFormatter / AnthropicMultiAgentFormatter
  Gemini:   GeminiChatFormatter / GeminiMultiAgentFormatter
  Ollama:   OllamaChatFormatter / OllamaMultiAgentFormatter
  DeepSeek: DeepSeekChatFormatter / DeepSeekMultiAgentFormatter
```

**TruncatedFormatterBase**: 继承 `FormatterBase`，增加 Token 截断能力，当消息超过模型上下文窗口时自动截断。

**设计意图**: 不同模型 API 的消息格式差异很大（如 Anthropic 不支持 `system` 角色、Gemini 使用 `contents` 而非 `messages`），格式化器封装了这些差异，使上层代码无需关心。

### 3.4 Memory 层设计

```
MemoryBase (工作记忆抽象基类)
  ├── InMemoryMemory         — 内存列表（默认）
  ├── RedisMemory            — Redis 后端
  ├── AsyncSQLAlchemyMemory  — SQLAlchemy 异步
  └── TablestoreMemory       — 阿里云 TableStore

LongTermMemoryBase (长期记忆抽象基类)
  ├── Mem0LongTermMemory           — Mem0 长期记忆
  ├── ReMePersonalLongTermMemory   — 个人记忆
  ├── ReMeTaskLongTermMemory       — 任务记忆
  └── ReMeToolLongTermMemory       — 工具记忆
```

**工作记忆 vs 长期记忆**:
- **工作记忆**: 存储对话历史消息，每次 `reply` 前加载，用于构造 LLM 输入
- **长期记忆**: 跨会话持久化，支持主动检索和记录，以工具函数形式提供给 Agent

**记忆压缩机制** (ReActAgent):
```
当 Token 数 > trigger_threshold 时:
1. 保留最近 keep_recent 条消息
2. 将历史消息发送给压缩模型
3. 使用 SummarySchema 生成结构化摘要:
   - task_overview: 任务概述
   - current_state: 当前状态
   - important_discoveries: 重要发现
   - next_steps: 后续步骤
   - context_to_preserve: 需保留的上下文
4. 用摘要消息替换历史消息
```

### 3.5 Tool 层设计

```
Toolkit (工具集管理器, 继承 StateModule)
  ├── 注册工具函数
  │   ├── 普通 Python 函数 (自动解析 docstring 生成 schema)
  │   ├── MCP 工具函数 (MCPToolFunction)
  │   └── Agent 技能 (AgentSkill)
  ├── 工具组 (ToolGroup)
  ├── 中间件链 (_middlewares)
  └── 工具执行 (支持并行)
```

**Toolkit 设计要点**:

1. **自动 Schema 生成**: 通过 `_parse_tool_function` 解析函数签名和 docstring，自动生成 OpenAI function calling 格式的 schema
2. **MCP 集成**: `MCPToolFunction` 封装 MCP 协议工具，支持 HTTP 和 Stdio 两种传输方式
3. **中间件模式**: 工具执行支持中间件链，可在工具调用前后插入自定义逻辑
4. **Meta Tool**: `reset_equipped_tools` 允许 Agent 运行时动态切换工具集
5. **并行工具调用**: `parallel_tool_calls=True` 时，使用 `asyncio.gather()` 并行执行多个工具调用

### 3.6 Pipeline 层设计

```
Pipeline 设计模式:

1. SequentialPipeline (顺序模式):
   Input → Agent1 → Agent2 → Agent3 → Output

2. FanoutPipeline (扇出模式):
         ┌→ Agent1 → Output1
   Input ─┼→ Agent2 → Output2   (可并行)
         └→ Agent3 → Output3

3. MsgHub (广播模式):
   Agent1 ←broadcast→ Agent2 ←broadcast→ Agent3
   (所有 Agent 的回复自动广播给其他 Agent)

4. ChatRoom (实时语音聊天室):
   RealtimeAgent1 ←→ ChatRoom ←→ RealtimeAgent2
   (基于 WebSocket 的实时语音对话)
```

**MsgHub 核心机制**:
- 使用上下文管理器 (`with MsgHub(...)`) 管理生命周期
- 进入时注册参与者，退出时清理
- 每个参与者 reply 后，消息自动 broadcast 给其他参与者
- 支持 `announcement` 初始公告消息
- 通过 `AgentBase._subscribers` 实现订阅-发布

### 3.7 RAG 层设计

```
KnowledgeBase (知识库抽象)
  ├── embedding_model: EmbeddingModelBase    # 嵌入模型
  ├── embedding_store: VDBStoreBase          # 向量存储
  ├── retrieve(query) → list[Document]       # 检索
  └── add_documents(documents)               # 索引

Document (文档模型)
  ├── content: dict   # 文档内容（text/metadata）
  └── score: float    # 相关性分数

Reader 层:
  TextReader / PDFReader / DocxReader / ExcelReader / PPTReader

Store 层:
  QdrantStore / MilvusStore / MongoDBStore / OceanBaseStore
```

**与 ReActAgent 的集成**:
- RAG 以 `KnowledgeBase` 形式注入 ReActAgent
- 每次回复前自动检索相关知识
- 支持 `enable_rewrite_query` 让 Agent 重写查询以提升检索质量

### 3.8 MCP 层设计

```
MCPClientBase (MCP 客户端基类)
  ├── name: str                            # 唯一标识
  ├── get_callable_function(func_name) → Callable  # 获取工具函数
  └── _convert_mcp_content_to_as_blocks() # MCP 内容 → AS Block 转换

StatefulClientBase (有状态客户端基类)
  ├── HttpStatefulClient    # HTTP 有状态
  └── StdioStatefulClient   # Stdio 有状态

HttpStatelessClient          # HTTP 无状态客户端
```

**MCP 与 Toolkit 的集成**:
- `MCPToolFunction` 继承 `RegisteredToolFunction`，封装 MCP 工具
- Toolkit 的 `add_mcp_client()` 方法将 MCP 服务工具注册到工具集
- MCP 返回的多模态内容自动转换为 AgentScope 的 ContentBlock

## 4. 横切关注点设计

### 4.1 可观测性 — Tracing

基于 **OpenTelemetry** 标准，提供全链路追踪：

| 追踪点 | 装饰器 | 说明 |
|---|---|---|
| LLM 调用 | `trace_llm` | 记录模型名、输入 Token、输出 Token |
| Agent 回复 | `trace_reply` | 记录 Agent 名称、输入输出消息 |
| 格式化 | `trace_format` | 记录格式化器信息 |
| 工具调用 | `trace_toolkit` | 记录工具名称、参数、结果 |
| 嵌入调用 | `trace_embedding` | 记录嵌入模型信息 |

**集成方式**:
- 通过 `agentscope.init(tracing_url=...)` 启用
- 支持第三方平台: Arize-Phoenix、Langfuse 等
- 与 AgentScope Studio 原生集成

### 4.2 状态管理 — StateModule

`StateModule` 是所有有状态组件的基类，提供：
- 状态序列化/反序列化
- 状态快照和恢复
- 被 `AgentBase`、`Toolkit` 等继承

### 4.3 会话持久化 — Session

```
SessionBase (会话基类)
  ├── JSONSession          — JSON 文件存储
  ├── RedisSession         — Redis 存储
  └── TablestoreSession    — TableStore 存储
```

Session 负责将 Agent 的运行状态（记忆、对话历史等）持久化，支持跨进程恢复。

### 4.4 全局配置 — ContextVar

`_run_config.py` 使用 Python 的 `ContextVar` 实现线程安全和异步安全的全局配置：

```python
_config = _ConfigCls(
    run_id=ContextVar("run_id"),
    project=ContextVar("project"),
    name=ContextVar("name"),
    created_at=ContextVar("created_at"),
    trace_enabled=ContextVar("trace_enabled"),
)
```

**设计意图**: 在异步环境中，全局变量容易引发竞态条件，`ContextVar` 确保每个协程拥有独立的配置副本。

### 4.5 Hook 机制

AgentBase 的 Hook 机制是框架的**核心扩展点**：

```python
# 类级别 Hook — 对所有实例生效
AgentBase._class_pre_reply_hooks["studio"] = studio_hook

# 实例级别 Hook — 仅对特定实例生效
agent._instance_pre_reply_hooks["custom"] = custom_hook
```

**Hook 执行流程**:
```
pre_reply_hooks → reply() → post_reply_hooks
pre_observe_hooks → observe() → post_observe_hooks
pre_print_hooks → print() → post_print_hooks
```

**应用场景**:
- Studio 集成: 通过 Hook 将 Agent 消息推送到 Web UI
- 日志记录: 在 `post_reply` 中记录 Agent 行为
- 输入修改: 在 `pre_reply` 中修改 Agent 输入参数
- 输出修改: 在 `post_reply` 中修改 Agent 输出消息

## 5. 设计模式总结

| 设计模式 | 应用位置 | 说明 |
|---|---|---|
| **策略模式** | Model / Formatter / Memory / VDBStore / Embedding | 可插拔的算法/实现替换 |
| **观察者模式** | MsgHub / Agent._subscribers | 消息订阅与广播 |
| **模板方法模式** | AgentBase (reply/observe/print) | 定义算法骨架，子类实现具体步骤 |
| **组合模式** | ReActAgent (组合 Model+Formatter+Toolkit+Memory+...) | 灵活组合各种能力 |
| **中间件模式** | Toolkit._middlewares | 工具调用前后插入自定义逻辑 |
| **上下文管理器** | MsgHub | 管理资源的生命周期 |
| **工厂模式** | _AgentMeta 元类 | 自动注册和创建 Agent 类 |
| **装饰器模式** | trace_llm / trace_reply 等 | 透明地添加追踪能力 |
| **适配器模式** | Formatter / MCPClient | 适配不同 API 格式 |
| **状态模式** | SubTask (todo/in_progress/done/abandoned) | 子任务状态机 |

## 7. 数据流

### 7.1 单 Agent 对话流

```
User Input
    │
    ▼
UserAgent.reply() → Msg
    │
    ▼
ReActAgent.observe(msg)  ──→ Memory.add(msg)
    │
    ▼
ReActAgent.reply()
    │
    ├─→ Memory.get()              # 获取对话历史
    ├─→ KnowledgeBase.retrieve()  # RAG 检索 (可选)
    ├─→ Formatter.format()        # 格式化消息
    ├─→ Model(messages)           # 模型推理
    │       │
    │       ├─ 文本响应 → 构造 Msg → return
    │       ├─ 工具调用 → Toolkit.execute() → 将结果加入 Memory → 继续循环
    │       └─ 结构化输出 → 构造 Msg → return
    │
    ▼
ReActAgent.print(msg)     # 输出/播放
    │
    ▼
Msg 返回给调用者
```

### 7.2 多 Agent 协作流 (MsgHub)

```
with MsgHub(participants=[agent1, agent2, agent3]):
    # agent1 回复 → 自动 broadcast 给 agent2, agent3
    msg1 = await agent1.reply()
    # agent2 回复 → 自动 broadcast 给 agent1, agent3
    msg2 = await agent2.reply()
    # ...
```

内部机制:
```
agent1.reply() → msg
    → agent2.observe(msg)
    → agent3.observe(msg)
```

## 8. 与外部系统的集成

### 8.1 AgentScope Studio

通过 `agentscope.init(studio_url=...)` 集成：
- 注册运行实例
- 替换 UserAgent 输入方式为 `StudioUserInput`
- 挂载 Studio Hook 实现消息推送
- 提供 Tracing 端点

### 8.2 MCP 协议

通过 `Toolkit.add_mcp_client()` 集成：
- HTTP 有状态/无状态客户端
- Stdio 有状态客户端
- 自动转换 MCP 内容为 AgentScope Block

### 8.3 A2A 协议

通过 `A2AAgent` 和解析器集成：
- File 解析器: 本地配置文件
- Nacos 解析器: 服务发现
- WellKnown 解析器: 标准发现协议

### 8.4 OpenTelemetry

通过 `agentscope.init(tracing_url=...)` 集成：
- OTLP 导出
- 兼容 Arize-Phoenix、Langfuse 等平台
